# Architecture

## Architectural intent

LearnQuick is a local-first education product for macOS. Its core lesson workflow must not require a remote backend, an account or a persistent network connection.

## Current implementation (v1.0)

The working application lives in `app/` and runs in the browser from a double-click on `LearnQuick.html`.

```text
app/
  index.html               # Design-kit shell; classic <script> tags in dependency order
  css/kit.css              # Design system (tokens, cards, meters, rings, modal, toast…)
  css/app.css              # Application layer (lessons, sessions, trainers, progress…)
  js/core/
    util.js                # Dates, escaping, answer normalization, seeded shuffles
    calendar.js            # US federal holidays, eligible study days, plan schedule, daily tasks
    srs.js                 # Leitner spaced repetition
    streak.js              # Streak and freeze rules (pure functions)
    verbs.js               # Conjugator: 25 verbs × 8 tenses
    progress.js            # State shape, migration, XP, answers, plan status, achievements
    store.js               # localStorage, persistence request, backup export/import, demo state
  js/content/
    units.js               # 25 lessons: vocabulary, grammar hack, dialogue, exercises, speaking
    practice.js            # Trainer data, resources, missions, placement test, B1 mock exam
  js/ui/
    components.js          # Shared HTML builders, toast queue, modal, celebrations, shadowing
    speech.js              # Voice selection, text-to-speech, optional recognition and recording
    exercises.js           # Exercise builders and the session runner
  js/views/                # One module per screen; returns HTML or { html, mount }
  js/app.js                # Hash router, delegated events, top bar, ⌘K search, activity timer
tests/                     # node:test suites loading the same files in Node
```

Key decisions:

- **No build step and no dependencies.** ES modules and `fetch` are blocked on `file://`, so every file is a classic script that attaches to a global `LQ` namespace. Every file also exports itself for Node, so the tests exercise the real code.
- **Pure core.** Scheduling, streak, SRS and conjugation are deterministic functions of the state and an injectable clock (`LQ.util.clock`), and are unit-tested.
- **Event-derived metrics.** Answers and minutes are recorded per day in `state.activity`. Streak, accuracy, time in Spanish and readiness signals are computed from those records, never stored separately.
- **Delegated events.** Views render strings. Interaction goes through `data-go`, `data-action`, `data-speak`, `data-change`, `data-input` and `data-submit` attributes handled once in `app.js`.
- **Graceful degradation.** Speech synthesis, recognition, recording and persistent storage are detected at runtime. When they are missing, the related controls are hidden or explained instead of failing.

## Native application: C++20 + Qt 6 (decided 2026-11-01)

The native app lives in [`desktop/`](../desktop/README.md). The options considered were a Tauri wrapper, Python + PySide6, Swift + SwiftUI and C++ + Qt.

C++20 + Qt 6 was chosen for these reasons:
- **Develop on Windows, ship to Mac.** The maintainer works on Windows; CI produces a universal macOS binary that runs on Apple Silicon and Intel. Swift was set aside only because Xcode requires a Mac.
- **Engineering depth.** The project exercises CMake, compilation and linking, memory and threading, and the C++20 calendar library for the study-day rules.
- **On-device AI in the same language.** whisper.cpp (speech recognition) and llama.cpp (conversation practice) are C++ libraries with Metal acceleration on Apple Silicon.
- **No WebView.** The interface is Qt Quick (QML), drawn by Qt itself.

### Runtime stack

- **Presentation:** QML views that only describe screens and bind to C++ objects. Design tokens come from a `Theme` singleton mirroring `app/css/kit.css`.
- **Domain:** `lq_core`, a C++20 library with no Qt dependency: civil dates (`std::chrono::sys_days`), US federal holidays, study days, the 30/60/90-day schedules, streak and freezes, plan progress and pace. Since phase 3 it also loads the course (nlohmann/json) and holds answer checking, Leitner spaced repetition, the conjugator, the exercise builders and sessions, and the B1 mock scoring. Since 0.3.2 it also holds the coach: prioritized suggestions from the learner's state, the taste learned from their reflections, and the taste-weighted draw of mixed practice. Pure functions over value types, unit-tested with Catch2. The JavaScript `app/js/core/` is the specification: golden-master tests compare the C++ results with output generated by the web engine (`desktop/tools/web_reference.js`).
- **Persistence:** `lq_storage`, SQLite through Qt SQL, with numbered migrations tracked in `PRAGMA user_version`; a database from a newer app version is refused. Phase 2 stores the learner profile, including the reason for learning Spanish in the learner's own words. Phase 3 (schema 2) stores the learner's progress in the same shape as the web app's state: plan days, ticked tasks, unit and checkpoint results, daily activity and answer tallies, review cards, streak and frozen days. Schema 3 (0.3.2) adds the learner's reflections and the session count behind them. Schema 4 (0.3.5) adds the emoji the learner picked for their streak. Schema 5 (0.3.6) adds a key/value `setting` table for the Settings screen (day or night, the learner's voice, normal and slow pace), so a new setting needs no migration. Schema 6 (0.4.0) adds the immersion log, language exchanges, device missions and achievements, and the web app's days off and holiday choice in the profile. Schema 7 (0.4.5) forgets the saved voice and paces, whose meaning changed, so every learner starts from the new recommended ones. The whole state is written in one transaction after every change. Backups use the web app's JSON format, so each app restores the other's (`lq_core`'s `backup.cpp`); desktop-only data travels under `state.desktop`, and a restore replaces the profile and the progress in one transaction.
- **Learner context:** the first-run welcome flow, always in English, asks for a name, the reason for learning Spanish (free text), goals, level and plan length. The reason is shown on the Today screen and will be passed as context to the phase-5 conversation practice. It never leaves the computer.
- **Content:** the whole course (units with vocabulary, grammar, dialogues and exercises; trainer material; the mock exam) exported from `app/js/content/` to `desktop/content/course.json`, compiled into the app.
- **Speech:** a neural Spanish voice ships with the app (`lq_voice`), run by onnxruntime on the CPU, offline. Since 0.3.4 it is Supertonic 2 (OpenRAIL-M), with the app's own C++ inference, a voice for each dialogue character (`lq::voiceFor`) and, since 0.3.5, a learner's pace (adjustable in Settings since 0.3.6; the speech latents are stretched before the vocoder up to 1.25 and the sound with WSOLA for the rest, which since 0.3.6 removes most of the metallic echo). Since 0.4.5 every voice is stretched by its own measured pace to a common one (0.83× of 4.8 syllables a second by default, 0.74× when slow), the pauses between sentences are drawn out to 0.6 s (1.5 s when slow), each voice has its own noise seed, and each phrase is filtered (80 Hz high-pass, +1.5 dB at 3.2 kHz) and levelled to −18 dBFS of speech; M2 narrates; from 0.3.1 to 0.3.3 it was Piper `es_MX-ald-medium`, fed by an own C++ phonemizer in `lq_core` that matches espeak-ng (GPL-3.0, not linked). Symbols and numbers are read as words ("a / b" → "a o b", "305" → "trescientos cinco"), and misread names are respelled ("Ohio" → "Ojáio"). The system voices (Qt TextToSpeech, Mexican Spanish preferred) remain as a fallback. whisper.cpp comes next for on-device recognition. Microphone and speech usage descriptions go in `Info.plist`.
- **Packaging:** `cmake --install` runs Qt's deployment step (`macdeployqt` / `windeployqt`) and adds the offscreen platform plugin, which the deployment tools skip. CI runs the packaged app's smoke test with the runner's Qt removed from the environment. CI ad-hoc signs the bundle and builds a `.dmg`. Developer ID signing and notarization come with the release milestone.

### Module boundaries (target)

```text
desktop/
  CMakeLists.txt
  core/                      # lq_core: dates, calendar, streak, progress, demo learner, course,
                             #   answers, srs, verbs, exercises (no Qt)
  storage/                   # lq_storage: SQLite connection, migrations, profile, progress
                             #   phase 4: backup import
  src/                       # The app: bootstrap, command line and view models (QObject)
                             #   bridging core/storage and QML (ProfileController, LearnerController,
                             #   TodayModel, SessionModel, SpeechController)
  *.qml                      # Screens and components: Main, Welcome, Shell, TodayPage, LessonPage, ...
  content/course.json        # Course data exported from the web app
  tests/                     # Catch2: engine, parity with the web engine, storage
  tools/                     # Node exporters that read the web app
  speech/                    # Phase 5: whisper.cpp, llama.cpp
```

`speech/` does not exist yet.

## Data flow

1. A presentation component dispatches an explicit user intent (start lesson, submit answer, change schedule).
2. An application service validates the command and resolves the current domain state.
3. The service performs a transactional write through the storage abstraction.
4. Derived metrics are recomputed from persisted learning events.
5. View models expose immutable presentation data to the QML views.

Avoid persisting calculated statistics independently unless there is a measured performance requirement. Persist the underlying event stream so metrics remain reproducible.

## Non-functional requirements

- Full core study flow available without Internet access.
- No implicit uploads of microphone recordings or learner history.
- Keyboard-accessible navigation, sufficient contrast and correct focus management.
- Local schema migration and recoverable backups.
- Deterministic calendar calculations with explicit timezone and holiday policies.
- UI/main-thread isolation for audio and long-running tasks.
- Reproducible builds and dependency version pinning before production.

## Out of scope for v1.0

Authentication, cloud synchronization, payments, live tutoring, generative AI evaluation, notarized distribution and automatic pronunciation scoring are not implemented.
